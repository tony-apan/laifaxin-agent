# 遇到解决不了的问题：向官方反馈

本技能覆盖的接口与流程都经过实测，但有些问题只会在真实账号环境里出现（典型：用户自己绑定的邮箱通道、特定服务商的返回、文档与接口不一致）。你按技能文档和接口目录排查后仍解决不了时，不要反复猜参数硬试，按下面流程把问题反馈给官方，让用户的每一次卡住都变成技能的改进。

## 什么时候反馈

- 同一操作按文档的做法连续失败，且报错不在已知对照里；
- 接口返回与目录/文档描述明显不一致；
- 绑定邮箱相关的异常（发件标识取到了仍报发送类错误等）；
- 用户明确说「帮我反馈给官方」。

## 反馈前先整理（只整理这几项）

1. 技能版本（SKILL.md 的 version）；
2. 用户想做什么、你执行了哪几步（到失败那一步为止）；
3. 报错原文（整段保留，不要改写、不要翻译）；
4. 相关参数：发件标识 sender / maid、邮箱服务商、涉及的接口路径。

**红线：绝不收集、绝不外发用户的授权凭据（token）、账号密码、邮箱密码/授权码、用户码、设备码。** 反馈只需要上面四项，凭据对定位问题没有用。

## 通道一：GitHub 提单（首选）

把整理好的内容拼成一张预填好的 Issue，打开链接给用户看，用户确认后由用户本人点「Submit new issue」提交（GitHub 提单必须用用户自己的账号，技能不要替用户保管 GitHub 凭据）：

```
https://github.com/tony-apan/laifaxin-agent/issues/new?template=feedback.md&title=<URL编码的标题>&body=<URL编码的正文>
```

标题格式：`[反馈] <问题一句话>`。正文按模板栏目逐项填好。正文拼好后先完整展示给用户过目，用户点头再打开链接。

## 通道二：邮件兜底

用户没有 GitHub 账号或打不开提单页时，把同样内容整理成一封邮件发给 **help@zhijixinxi.com**，标题格式同上，正文栏目同模板。发送前同样先给用户看全文，用户确认再发。

## 提交之后

告诉用户：官方收到后会处理，修好后会在单里/邮件里回复，并随技能新版发布。后续用户问起进展时，可带他去原单查看，不要重复提交同一问题。
